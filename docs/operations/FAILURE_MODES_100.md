## 🔴 КАТЕГОРИЯ А: КРИТИЧЕСКИЕ (Остановка игры)

### A1. База данных пользователей недоступна
**Симптом:** Все API запросы возвращают 500. `/api/health` показывает DB: disconnected.
**Причины:**
- PostgreSQL упал (OOM, диск полон, коррупция данных)
- Сетевой разрыв между API и БД
- VPC security group блокирует порт 5432
**План действий (20/80 — главное):**
1. `kubectl get pods -n signal-arena | grep db-users` — проверить статус пода
2. `kubectl logs sa-db-users-0 -n signal-arena --tail=50` — посмотреть логи
3. Если OOM: `kubectl edit statefulset sa-db-users` — увеличить memory limit
4. Если диск: `kubectl get pvc -n signal-arena` — проверить PVC
5. **Крайний случай:** `kubectl rollout undo statefulset/sa-db-users`
6. Время восстановления: 2-5 минут при работающем бэкапе

### A2. Redis недоступен (боевые сессии теряются)
**Симптом:** Игроки не могут начать бой. Ошибка "Session expired".
**План:**
1. `kubectl get pods -n signal-arena | grep redis`
2. Если упал: `kubectl delete pod sa-redis-xxx` (авторестарт)
3. Игроки в активном бою потеряют прогресс → выдать компенсацию (+5 AP)
4. Включить in-memory fallback (автоматически в коде)
5. Время: 30 секунд на рестарт Redis

### A3. K8s кластер недоступен
**Симптом:** Всё лежит. Cloudflare показывает 502/503.
**План:**
1. Проверить статус нод: `kubectl get nodes`
2. Проверить баланс облачного аккаунта (не закончились ли кредиты)
3. Если ноды в NotReady: перезапустить через облачную консоль
4. Запасной план: `docker-compose up -d` на резервном VPS
5. Время: 5-15 минут

### A4. SSL сертификат истёк
**Симптом:** Браузеры показывают "Connection not secure".
**План:**
1. `kubectl get certificate -n signal-arena` — проверить статус
2. `kubectl delete certificate sa-tls-cert` — принудительный перевыпуск
3. cert-manager автоматически запросит новый у Let's Encrypt
4. Время: 2-5 минут

### A5. DNS не резолвится
**Симптом:** api.signalarena.io не открывается.
**План:**
1. Проверить Cloudflare DNS: A-запись указывает на IP балансировщика
2. Проверить IP балансировщика: `kubectl get svc -n ingress-nginx`
3. Если IP изменился: обновить DNS (TTL 5 минут для быстрого восстановления)
4. Время: 5-30 минут (зависит от DNS propagation)

## 🟠 КАТЕГОРИЯ B: ВЫСОКИЕ (Частичная деградация)

### B1. Контент-пакеты не применяются
**Симптом:** Новые сценарии не появляются в игре. Pull agent в логах пишет ошибки.
**План:**
1. Проверить staging bucket доступность
2. Проверить HMAC подпись — возможно, ключ шифрования изменился
3. Ручной запуск: `kubectl exec -it deploy/signal-arena-api -- node src/content/pull-agent.js`
4. Если проблема с конкретным пакетом — удалить его из staging

### B2. Утечка памяти в API
**Симптом:** Поды рестартуют по OOMKilled. Response time растёт.
**План:**
1. `kubectl top pods -n signal-arena` — посмотреть потребление
2. Увеличить лимиты: `kubectl edit deployment signal-arena-api`
3. Проверить утечку в коде (скорее всего — broker message queue не чистится)
4. Временное решение: увеличить реплики (HPA сделает это автоматически)

### B3. WebSocket соединения обрываются
**Симптом:** Игроки видят "Connection lost" в live-дуэлях.
**План:**
1. Проверить Ingress timeout: `kubectl edit ingress signal-arena-ingress` (proxy-read-timeout: 3600s)
2. Проверить Socket.io pingTimeout (должен быть 60000ms)
3. Увеличить keepalive в nginx: `keepalive_timeout 75s`

### B4. OpenRouter API недоступен
**Симптом:** Генерация сценариев падает. "API error" в логах.
**План:**
1. Проверить статус: https://status.openrouter.ai
2. Переключиться на fallback модель: google/gemini-2.0-flash-001
3. Если OpenRouter недоступен > 1 часа — использовать expert-режим (правила в коде)
4. Накопить запросы и отправить батчем когда API восстановится

### B5. Rate limiting блокирует легитимных игроков
**Симптом:** Игроки жалуются на 429 ошибки.
**План:**
1. Проверить логи: `kubectl logs -l app=signal-arena | grep "429"`
2. Увеличить лимит: `kubectl edit configmap` → RATE_LIMIT_MAX: 200
3. Добавить IP в whitelist (если это стример/инфлюенсер)
4. Время: 2 минуты

### B6. Токен падает — игроки паникуют
**Симптом:** -30% за день. Чат заполнен "RUG". Резкий рост exchange inflow.
**План:**
1. НЕ ПАНИКОВАТЬ. Проверить: это organic sell-off или скоординированная атака?
2. Если organic: усилить sink-механики (limited skins, boosted burns)
3. Если атака: использовать treasury для buyback (если governance разрешает)
4. Коммуникация: пост в Discord/Twitter с метриками retention (показать что игра живёт)
5. Запустить "Diamond Hands" event: двойной XP для держателей $SIG
